# ML pipeline

No verified dataset is included. Do not add synthetic student records or publish performance claims. Place a permissioned, documented CSV in `ml/data/student_wellness.csv`; keep it out of version control. The expected features are numeric scales `mood`, `energy`, `sleep_quality`, `workload`, `concentration`, `stress`, `social_connection`, `study_hours`, and `break_frequency` (each scale must be defined in the dataset card). `target` is a dataset-defined label; document its meaning, provenance, consent, and license before training.

`training.train` validates labels/features, splits train/validation/test rows before fitting imputers/encoders, performs stratified cross-validation for candidate classifiers, and reports actual held-out accuracy, precision, recall, F1, ROC-AUC where defined, and confusion matrix. It trains Random Forest, XGBoost, LightGBM and probability averaging, selects a candidate on validation macro-F1, and saves the complete preprocessing/model pipeline plus metadata. A locked test set is used once for reporting. Check class imbalance and calibration before deployment; the initial pipeline is not validated for clinical use or demographic fairness.

Artifacts are versioned local files and are not committed. Inference loads only `MODEL_DIR/model.joblib`; the service does not accept a caller-supplied path. Explanations use SHAP permutation attribution against a stored training background sample. They are model feature contributions, not causal explanations, and are unavailable unless a compatible artifact and SHAP runtime are installed. Model output is not a diagnosis and should not be deployed until data governance, evaluation, calibration, bias assessment, and human review are complete.
